## 安装与更新

兼容目标：DSH **0.2.2-rc.1**。预构建包包含客户端、SMLib WebAssembly 内核与运行依赖，不需要手动安装依赖或构建，也不需要 Python。

桌面版：打开 DSH「插件」→「添加插件」，输入 npm 包名 `dsh-minicad`，点击「安装」并启用，按提示重启。桌面配置由应用管理，不通过 CLI 修改。

本地安装：解压发布安装包，保留其中的 `node_modules`，在「添加插件」中输入解压后的 `package` 目录（例如 `link:C:/MiniCAD/package`）。

### Web 安装

需要 Node.js 22.19+ 和 pnpm。没有 pnpm 时先执行：

```sh
npm install -g pnpm
npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web add dsh-minicad -w
```

安装本地包时，将 `dsh-minicad` 换成解压目录，例如 `link:C:/MiniCAD/package`；macOS/Linux 使用 `link:/absolute/path/to/package`。已有全局 dsh 时，可用 `dsh` 替代 `npx @deepseek-ai/dsh@0.2.2-rc.1`。安装后重启 Web 宿主。

没有 pnpm 的 Web 配置也可手动安装：把解压后的 `package` 目录放到目标 profile 的 `node_modules/dsh-minicad`，将 [cordis.patch.yml](../cordis.patch.yml) 的完整条目合并到该 profile 的补丁数组。不要在已有 `[]` 后直接追加 YAML；此方式不适用于桌面版。

桌面版 npm 安装更新时，先在「插件」页卸载，再按包名重新安装。Web npm 安装通过 `npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web update dsh-minicad -w` 更新，随后重启。更新本地安装包时，解压到独立目录，在插件管理中切换到新目录并重启；不要覆盖自己的设计文件夹。

## 建模、核验与导出

- 一个设计对应一个普通工作文件夹。同一设计的会话共享模型与历史，各自保留独立聊天上下文；「另存为」创建独立方案。
- 用对话提出或修改需求。PDF 图纸需由 agent 实际读取页面；读取能力取决于宿主可用的 PDF 工具与支持图片的模型。尺寸或视图有歧义时先澄清。
- 双击画布打开输入框；顶部把手可拖动或固定。主题与语言跟随 DSH。
- 输入框按实际换行展开。固定输入框不会阻止 Esc 退出选择或关闭版本对比。
- 成功完成后，顶部状态更新但不自动展开详情；点击状态可查看，详情不会定时收起。
- 窄工作台默认收起设计导航，版本库、制作记录和版本对比优先使用内容区域。左上角导航按钮可切回设计列表。列表支持 Tab 聚焦、方向键导航、Enter 打开和 Shift+F10 操作菜单。
- 移动鼠标时，画布右下角显示世界 X/Y/Z 坐标，单位为 mm。指向模型时按预览表面取点，指向空白处时取视线与 XY 平面的交点。
- 「选择目标」进入选择模式，默认同时选面和边；当前模型为多实体装配体时同时打开模型查看面板，单实体不显示面板。再次点击入口或关闭面板退出。单击替换，Ctrl+单击增减，空白或 Esc 清除。选择后可测量，或通过「引用」把目标与修改要求加入对话。
- 鼠标悬浮在实体上时显示名称；选中面或边后，选择工具栏显示所属实体的名称。agent 必须为每个最终实体按用途命名，装配体集合不需要整体名称。
- 单选面显示面积和面积质心，单选边显示长度和端点。圆边、球面和圆柱面还显示半径及各自的几何中心。坐标采用世界 X/Y/Z，单位 mm。双选测最小/最大距离及最近点连线在各轴的绝对分量。三个及以上目标不提供测量。带 `≈` 的数值是近似结果，面积单位 mm²。
- 点击工作台左上角的分支图标，打开当前模型文件的版本库。选中一条历史版本可预览，点击「切换到」才将它设为当前版本。下一次编辑从它分支，版本号继续递增。源码、参数或资源有未构建的修改时，先完成构建再切换。
- 「制作记录」回看保存版本、过程步骤与完整会话。建模失败或停止仍保留已保存模型。
- 「版本对比」展示基准版相对目标版的精确体积差异：绿为新增、红为删除、灰为共同部分。对比不修改模型，期间暂停选择与测量。
- 需要文件时让 agent 导出 STEP、STL 或项目 ZIP。右上角原生导航菜单可打开设计目录，也可将当前保存版本交给 FreeCAD；外部修改不会自动写回。

- 点击显示模式图标，按实体、线框、透明循环切换，图标和悬浮提示反映当前模式。版本对比期间仅切换实体和线框。多实体装配体的模型查看面板中，点击零件左侧的眼睛图标切换显隐，「显示全部」恢复所有零件。这些操作不改变模型、版本或导出内容。
- 工作台显示模型保存的工件颜色，单面颜色优先于工件颜色。可让 agent 给指定工件或面上色。
- 同一设计有多个模型或规格时，在「选择目标」中选择对应文件。单实体只显示紧凑的模型切换控件，多实体装配体还显示零件显隐。模型与规格、外部应用菜单打开时，测量和引用浮层暂时收起，关闭菜单后恢复。让 agent 生成不同参数的规格，并按需分别导出整组或某个零件。
- 多零件模型由 agent 创建并命名，零件接触不会自动合并；可让 agent 检查零件之间的间隙与干涉。

几何有效与尺寸检查不等于结构强度或加工可行性验证。

### FreeCAD 路径

插件自动通过 PATH、Windows 注册信息或 macOS 应用索引查找 FreeCAD。未检测到时，可在 DSH 的 `minicad` 配置中填写自己的路径：

```yaml
- id: minicad
  config:
    freecadExecutable: C:/Program Files/FreeCAD/bin/FreeCAD.exe
```

空字符串使用自动检测；Linux AppImage 等非 PATH 安装也可指定绝对路径。补丁会替换整行配置，已有其他配置时一并保留。

## 数据与运行边界

- 原生实体统一使用 `.smp`。旧 `.smb` 历史快照不再读取或自动迁移；旧源码需重新构建。
- 设计目录保存源码、参数、精确实体、`.cad-design.json` 和 `.cad-history/`；复制整个文件夹可带走模型与版本。聊天记录由 DSH 保存。
- `.cad-process/` 保存建模过程，`references/` 保存参考图纸，`exports/` 保存导出结果。未提交试算不随「另存为」复制。
- 已打开设计的索引位于 `$DSH_HOME/storages/minicad/designs.json`；默认 DSH_HOME 为 `~/.dsh`，`dataDir` 可覆盖索引目录。
- 设计重命名会同步更改文件夹名称及关联会话的工作目录；「移除」只关闭列表登记，保留文件和会话。
- 内核在独立 Node 进程中执行，默认任务超时 120 秒。停止会终止建模进程并保留已提交版本。进程隔离不是安全沙箱；只运行可信设计代码。
- 不要让多个 DSH 进程同时写入同一 MiniCAD 数据目录。

## 排障与移除

| 问题 | 处理 |
| --- | --- |
| 没有 MiniCAD 入口 | 确认装在正确的 profile，启用后重启 DSH |
| 预构建包无法启动内核 | 确认完整解压并保留了包内 `node_modules`；必要时重新解压 |
| 源码安装无法启动 | 执行下方的依赖安装与构建命令 |
| 模型认证失败 | 检查 DSH 中的模型配置或登录状态 |
| 模型不显示 | 检查图形加速/WebGL，并确认已有成功保存的模型 |
| 版本冲突 | 让 agent 重新读取当前版本后修改 |
| HTTP 401 / 404 | 分别检查宿主登录状态、profile 与插件启用状态；401 不证明路由已注册 |

桌面版通过「插件」页移除；Web 使用：

```sh
npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web remove dsh-minicad -w
```

重启后入口消失。卸载不删除设计数据。

## 从源码运行

在仓库目录使用 Node.js 22.19+：

```sh
npm ci
npm run setup
```

在桌面插件页或 Web CLI 安装 `link:仓库的绝对路径`。客户端改动重新构建后支持 DSH HMR，主机改动需重启。

```sh
npm run dev
npm run check
npm test
npm pack --pack-destination dist
```

打包前创建 `dist` 目录。`npm pack` 自动构建并包含运行依赖；GitHub 源码 ZIP 不包含这些预构建内容。

`dev` 使用真实 DSH 的 `minicad-dev` profile（端口 3079、数据目录 `.local/designs`），沿用 DSH_HOME 中的设置与凭据。`PORT` 可覆盖端口；`DSH_ELECTRON` 与 `DSH_CLI` 可分别指定已安装桌面版可执行文件及其内置 CLI。

`check` 只做语法与构建检查；`test` 串行运行建模内核测试。界面与真实 agent 交互由用户验收，约定见 [AGENTS.md](../AGENTS.md)。

维护者发布步骤见 [AGENTS.md 的发布约定](../AGENTS.md#发布)。
